### F-M3-001 — Legacy status is not current adequacy evidence
Old packages and checkpoints may say materialized/closed, but they are historical evidence only until reconciled against current decisions.

Existing v0.3.0 validation proves JSON Schema validity, extractor syntax and synthetic extraction smoke only. It does not prove ISO clause-level conformance, M2 adequacy, Kernel admission or production readiness.

### F-DS-001 — Legacy DS contamination risk
Old manuals and legacy Foundation contain prior tokens/components. Leivis explicitly ratified the newly supplied public visuals as current DS authority. Old DS values are migration/history evidence only.

### F-DS-002 — Exact current DS tokens not yet evidenced
Raster/public screenshots prove visual grammar but not exact canonical token values. Exact tokens remain UNKNOWN until recovered from current source/code or explicitly ratified.

## 6. M3 closure conditions

M3 cannot be recommended for closure until:

- denominator of required M3 constructs is frozen;
- each construct has source/rationale class;
- applicable normative evidence is traceable;
- M3 can express the current M2 core without hidden domain leakage;
- vNext changes, if any, are finding-driven;
- independent validators execute;
- Breaker scenarios execute;
- M0 pilot proves forward and inverse lineage;
- no material bypass remains;
- every residual HOLD/UNKNOWN has an owner and reason;
- Audit 360 is rerun after remediation.

Only Leivis can set `CLOSED_BY_AUTHORITY`.

## 9. Anti-false-closure

`PASS` is forbidden when:
- test denominator is zero but required > 0;
- validator did not run;
- extraction/atomization is empty where required;
- evidence is missing/lost;
- a bypass path exists;
- a superseded decision was used;
- normative applicability is unresolved and material.

The allowed states are `PASS`, `HOLD`, `BLOCKED`, `UNKNOWN`, `NOT_EXECUTED`, `NOT_VERIFIED`.
